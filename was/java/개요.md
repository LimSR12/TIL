# 1. 개요

## 프로젝트 진행 동기

부스트캠프 멤버십 과정 참여 초반에 Node.js 의 net 모듈만을 사용해 WAS를 구현해보라는 미션을 받아본 적이 있었다.

당시엔 Express를 사용해 백엔드를 구현해보고 학습하던 시기였던 걸로 기억하는데, Express라는 프레임워크가 해주는 것들이 실제로는 어떻게 이루어져있고 어떻게 동작하는지 뜯어보고 설계해서 구현해보라는 취지의 미션이었던 것 같다.

그래서 외부와 연결된 포트와 바인딩해 소켓 연결을 맺고, tcp 스트림으로 데이터가 들어오고, 어디부터 어디까지가 HTTP요청인지 파싱하는 등의 작업을 해봤었다.

그리고 약 6개월이 지난 시점에서, 자바 스프링 부트를 한참 공부하다보니 자바에서는 어떻게 실제로 구현해볼 수 있는지 문득 궁금해졌다. 스프링에서는 Servlet이 HTTP 요청 메시지를 읽어 파싱하고 응답해주는데, 이 서블릿 없이 직접 순수 자바로 WAS를 구현해보고 싶어졌다.

그래서 다음과 같은 프로젝트 목표를 세워봤다.

1. WAS를 원하는 포트에 띄울 수 있다.
2. TCP 스트림을 통해 들어온 데이터에서 HTTP 요청을 파싱하고 확인할 수 있다.
3. HTTP 요청을 컨트롤러에 넘겨주는 과정을 최대한 자세하게 분석하고 학습해본다.
4. (리서치 중 마음에 들어 추가한 목표) 동적 HTML 파일을 직접 제공하도록 구현해보고, 서블릿의 등장 이전의 불편함과 이후의 편리함을 체감해보기

# 3. 프로그램 클래스 구조 설계

## WAS 로직 흐름

1. 서버 소켓을 열고 클라이언트 연결을 기다린다.
2. 소켓 연결이 수립되면 클라이언트의 요청을 읽는다.
3. HTTP 요청 메시지를 파싱하여 추출한 데이터들을 애플리케이션 로직에서 사용할 수 있도록 객체에 담는다.
4. API 명세 스펙에 따라 알맞은 로직을 수행한다.
5. 로직 수행후 응답 객체를 반환하고, WAS는 응답 객체를 꺼내 HTTP 응답 메시지로 파싱한다.
6. 클라이언트에게 HTTP 응답 메시지를 전달한다.

## 클래스 역할 분리

- 소켓 통신 모듈
- HTTP - 객체 파싱 모듈
- 로직 호출 모듈
