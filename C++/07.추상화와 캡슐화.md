# 7-1 추상화와 캡슐화

## 추상화란?

추상화(Abstraction)는 복잡한 내부 구현은 숨기고, 외부에 꼭 필요한 특징과 동작만 뽑아서 드러내는 설계 기법이다!

- 현실 세계의 대상을 프로그램 안에 담아낼 때, 관심 있는 속성과 행위만 추려내는 과정이라고 생각할 수 있다.
- 예를 들어 `Car` 클래스를 설계할 때, 실제 자동차의 수많은 부품을 모두 모델링하지 않고 `speed`, `accelerate()`, `brake()` 같은 핵심만 남긴다.
- 클래스의 **인터페이스(무엇을 할 수 있는가)**와 **구현(어떻게 하는가)**을 분리하는 것이 가장 중요하다고 한다.

```cpp
class Car {
public:
  void accelerate();  // 외부에 드러낼 인터페이스
  void brake();
private:
  int rpm;            // 내부 구현 상세는 숨김
  void injectFuel();  // 내부에서만 쓰는 동작
}
```

## 캡슐화란?

**캡슐화(Encapsulation)**는 데이터(멤버 변수)와 그 데이터를 다루는 함수(멤버 함수)를 하나의 단위(클래스)로 묶고, 외부에서는 정해진 인터페이스를 통해서만 접근하게 제한하는 것이다!

추상화가 "무엇을 보여줄 지 결정하는 것"이라면 캡슐화는 "결정된 것을 어떻게 묶고 막을지"라고 이해할 수 있다.

또한 캡슐화는 객체 내부 상태의 불변조건(invariant)을 지킬 수 있게 해준다.

### 은닉화

은닉화는 캡슐화의 실천 방법 중 하나로, 내부 구현 세부사항을 외부로부터 숨기는 것이다.

멤버 변수는 원칙적으로 `private` 로 선언하고, 필요한 값만 `getter`/`setter` 를 통해 노출한다.

이렇게 하면 내부 구현이 바뀌어도 외부 코드가 영향받지 않게 만드는 효과가 있다!

```cpp
class Account {
private:
  int balance;      // 외부에서 직접 건드리지 못하도록 숨김
public:
  int getBalance() const { // const: 객체의 멤버 변수 값은 변경하지 않겠다는 뜻
    return balance;
  }
  void deposit(int amount) {
    if (amount > 0 ) balance += amount;
  }
}
```

### 접근 지정자

C++ 기준 접근 지정자는 다음과 같다.

| 지정자      | 같은 클래스 | 자식 클래스 | 외부 |
| ----------- | ----------- | ----------- | ---- |
| `public`    | O           | O           | O    |
| `protected` | O           | O           | X    |
| `private`   | O           | X           | X    |

- `public`: 어디서나 접근 가능하고, 클래스의 공개 인터페이스에 사용한다.
- `protected`: 해당 클래스와 파생 클래스에서만 접근 가능하다. 상속 구조에서 공유할 멤버에 주로 사용한다!
- `private`: 해당 클래스 내부에서만 접근 가능하다. class 키워드 기준 디폴트 접근 수준이다!

## 추상화와 캡슐화를 이용한 클래스 설계

좋은 클래스 설계의 흐름은 다음과 같다.

1. **추상화**: 해결하려는 문제에서 필요한 속성과 동작을 먼저 식별한다.
2. **캡슐화**: 식별한 속성과 동작을 하나의 클래스로 묶는다.
3. **은닉화**: 내부 상태는 `private`, 외부에 제공할 인터페이스만 `public` 으로 공개한다.
4. **인터페이스 설계**: 메서드 이름과 시그니처가 "무엇을 하는지" 명확히 드러내도록 한다.

# 7-2 상속성과 다형성

## 상속성이란?

상속(Inheritance)은 부모 클래스가 가진 멤버를 자식 클래스가 물려받는 기능이다.

상속을 사용함으로서 공통된 속성과 동작을 부모에 모아 중복되는 코드를 줄일 수 있다. 그러나 무분별하게 사용하는 것이 아니라 `"자식 is-a 부모"` 관계가 자연스러울 때 상속을 사용해야 한다. (`Dog is-a Animal`)

```cpp
class Animal {
public:
  void breathe() {
    std::cout << "숨쉬기" << "\n";
  }
}

class Dog : public Animal {
public:
  void bark() {
    std::cout << "멍멍" << "\n";
  }
}

Dog dog;
dog.breathe();
dog.bark();
```

### 단일 상속과 다중 상속

- 단일 상속(Single Inheritance): 하나의 부모 클래스만 상속받는다. Java, C# 등 대부분 언어에서는 단일 상속만 지원한다.
- 다중 상속(Mulitple Inheritance): 여러 부모 클래스를 동시에 상속받는다. C++ 에서만 지원하는 문제다!

```cpp
class A { public: void funcA() {} };
class B { public: void funcB() {} };

class C : public A, public B {}; // 다중 상속
```

그런데 이렇게 여러 클래스를 상속받는 경우 대표적으로 발생하는 문제가 **다이아몬드 문제**다. 공통 조상을 서로 다른 두 경로로 상속받으면 멤버가 중복되어 발생하는 문제이고, C++에서는 이 문제를 `virtual` 상속으로 해결한다.

```cpp
class Base { public: int x; };
class D1 : virtual public Base {}; // 가상 상속
class D2 : virtual public Base {};

class Final : public D1, public D2 {}; // Base::x 는 하나만 존재한다

```

## 다형성이란?

다형성(Polymorphism)은 같은 이름의 인터페이스가 상황에 따라 다르게 동작하는 성질이다.

즉, 같은 인터페이스를 사용하더라도 실제 객체나 타입에 따라 서로 다른 동작이 일어나는 성질을 말한다.

다형성은 컴파일 타임 다형성과 런타임 다형성으로 나눌 수 있는데, 각 특징은 다음과 같다.

### 1. 컴파일 타임 다형성(정적 다형성)

어떤 함수를 호출할 지 컴파일할 때 이미 결정되는 것이다.

대표적인 예시로 **함수 오버로딩**, **연산자 오버로딩**, **템플릿**이 있다.

#### 함수 오버로딩?

같은 이름의 함수지만, 매개변수의 개수나 타입이 다르면 여러 개 만들 수 있다!

```cpp
class Printer {
public:
  void print(int x) {
      cout << "int 출력: " << x << "\n";
  }

  void print(double x) {
      cout << "double 출력: " << x << "\n";
  }

  void print(string x) {
      cout << "string 출력: " << x << "\n";
  }
}
```

## 다형성을 활용한 유지보수성 향상

다형성을 잘 쓰면 OCP라고 하는 개방-폐쇄 원칙을 잘 지킬 수 있다.

개방 폐쇄 원칙이란 기존의 코드를 변경하지 않으면서, 기능을 추가할 수 있도록 설계가 되어야 한다는 원칙이다.
보통 OCP 를 확장에 대해서는 개방적이고 수정에 대해서는 폐쇄적이어야 한다는 의미로 많이들 정의한다.

> 확장에 열려있다?
>
> - 모듈의 확장성을 보장한다
> - 새로운 변경 사항이 발생했을 때 유연하게 코드를 추가함으로서 애플리케이션의 기능을 큰 힘을 들이지 않고 확장할 수 있다.
>
> 변경에 닫혀있다?
>
> - 객체를 직접적으로 수정하는 것은 제한해야 한다.
> - 새로운 변경사항이 발생했을 때 객체를 직접적으로 수정해야 한다면 새로운 변경사항에 대해 유연하게 대응할 수 없는 애플리케이션이다.

그래서 C++에서는 다형성을 잘 쓰면 틀래스에 새로운 타입을 추가하더라도 기존 코드는 수정할 필요 없이 확장만 하면 된다!

# 7-4 자신을 가리키는 this 포인터

## 객체가 메모리에 할당되는 구조

객체도 하나의 변수이므로 클래스 크기만큼의 메모리가 할당된다.
(클래스를 표현하기 위한 메모리, 멤버 변수를 저장하기 위한 메모리 등)

멤버 함수는 동일 클래스의 모든 인스턴스에서 공통으로 사용한다!
(멤버 함수는 메모리에 한번만 로드되고, 깉은 클래스의 인스턴스를 추가 생성하더라도 같은 위치의 함수를 사용한다.)

## this 포인터

멤버 변수와 멤버 함수는 메모리 위치가 다르다. 원칙적으로 멤버 함수에서는 멤버 변수의 주소를 모르기때문에 직접 값을 변경할 수 없는게 맞다. 그러나 멤버 함수에서 멤버 변수의 값을 참조하고 변경하며 프로그램이 정상적으로 동작할 수 있는 이유는 무엇??

객체의 메모리 주소를 this 포인터로 관리하기 때문이다!

this 포인터는 멤버 함수 내에서 자동으로 생성되어 해당 함수가 속한 객체의 주소를 참조한다

### 지역 변수와 구별할 때

```cpp
void bank::transfer_account(int safe) {
  this->safe = safe;
}
```

### 멤버 함수 체이닝을 구현할 때

여러 함수를 연이어 호출하는 방식인 함수 체이닝을 구현할때도 사용할 수 있다.
멤버 함수가 객체를 반환하고 해당 객체에서 다시 멤버함수를 호출하는 방식이고, 코드를 간결하게 만들면 호출 순서를 직관적으로 표현할 수 있다!

```cpp
global_back.deposit_interest(10).withdraw_utility(1).withdraw_tax(2);
```
